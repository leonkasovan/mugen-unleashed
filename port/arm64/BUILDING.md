# Build and test on ARM64 Linux

## Build on Windows

Check the device's libc before choosing the toolchain.

```powershell
ssh ark@192.168.7.2 'uname -m; ldd --version | head -1'
.\build.bat /setup
.\port\arm64\build.bat --setup
.\port\arm64\build.bat --check-tools
.\port\arm64\build.bat --jobs 8
```

ArkOS on the RG351MP uses glibc 2.30. Use the default Arm GNU 9.2
toolchain for that device. The port defaults to GLES and writes
`build/linux-arm64-aarch64-none-linux-gnu-sdl2/mugen-linux-arm64-aarch64-none-linux-gnu`.
See the [port README](README.md) for toolchain overrides, offline builds,
and dependency setup.

For a sprite benchmark without 3D models or video backgrounds, use an
isolated build directory. This example assumes the 9.2 toolchain,
x86devkit, and the ARM64 sysroot have already been installed.

```powershell
$env:Path = 'C:\arm-gnu-toolchain-9.2\bin;C:\x86devkit\bin;' + $env:Path
New-Item -ItemType Directory -Force build/tmp/arm64-test | Out-Null
$env:TMPDIR = (Resolve-Path build/tmp/arm64-test).Path.Replace('\', '/')
make -j8 MUGEN_TARGET=linux-arm64 CROSS_COMPILE=aarch64-none-linux-gnu- `
  XSYSROOT=build/sysroots/arm64-sysroot BUILD=build/tmp/arm64-test `
  MUGEN_GLES=1 MUGEN_MODEL3D=0 MUGEN_VIDEO_BG=0 SHELL=C:/x86devkit/bin/sh.exe
```

The normal ARM64 GLES build enables video backgrounds and requires the
`third_party/ffmpeg-7.1.5` submodule. Initialize it for a full build if
`configure` is missing:

```powershell
git submodule update --init third_party/ffmpeg-7.1.5
```

## Stage the test on the device

Use the existing game tree as the working directory. Keep the test binary,
backups, and output under its `build/tmp/` directory. This target is a
scratch copy, so it does not replace the launcher's executable.

```powershell
ssh ark@192.168.7.2 'cd /roms/ports/hdbz_indigo && mkdir -p build/tmp/arm64-test'
tar.exe -cf - -C build/tmp/arm64-test mugen-linux-arm64-aarch64-none-linux-gnu |
  ssh ark@192.168.7.2 'cd /roms/ports/hdbz_indigo/build/tmp/arm64-test && tar -xf -'
```

Run the binary transfer in **cmd.exe** or PowerShell 7.4 or later to keep
the native pipe binary safe. The device's SFTP subsystem may be unavailable.
The repository's `build.bat --upload` also uses tar over SSH and can target
a different directory with `--device-dir`.

Check the staged binary with `ldd` on the device. The build and the files in
`data/gles/` should come from the same revision. Back up the installed
shaders, configuration, and `mugen.log` before changing them for a test,
then restore them when the runs finish. For the atlas overlay comparison,
stage `font/atlas.f-4x6.sff` generated by `sffcli --atlas` from that
installation's `font/f-4x6.sff`. If Vegeta's DEF is named
`Normal_VegetaZ2.def`, create a temporary `VegetaZ2.def` in the same
directory only when that name does not already exist.

## Run the match

From an SSH session on the device:

```sh
cd /roms/ports/hdbz_indigo
chmod +x build/tmp/arm64-test/mugen-linux-arm64-aarch64-none-linux-gnu
MUGEN_SPRITEBATCH=1 MUGEN_FRAME_TRACE=build/tmp/arm64-test/match.csv \
  build/tmp/arm64-test/mugen-linux-arm64-aarch64-none-linux-gnu \
  -nosound -sessionseed 12345 -p1 GohanZ2 -p2 VegetaZ2 -s hdbz_lookout
```

Enable `[Debug] ShowFPS = 1` in the effective configuration. Confirm the log
shows Mali-G31, an effective OpenGL renderer, atlas support, and
`Match loop init`. The frame trace is written on orderly exit. For timing,
compare a 25-second window starting at the first rendered match frame.
Count rendered frames for FPS and average draw, presentation, and swap
times over rendered frames. Keep the seed, configuration, stage assets,
and font atlas the same between runs, and alternate the run order.

Once the trace has been written, this command summarizes the first
25 seconds of match frames using the trace's frame periods. It requires
the match to run past the end of the sample window.

```sh
awk -F, '
  NR > 1 && $2 == 4 && $10 > 0 && (started || $3 == 1) {
    started = 1
    if (elapsed >= 25000) exit
    elapsed += $10
    if ($3 == 1) { frames++; draw += $5; present += $7; swap += $8 }
  }
  END {
    if (elapsed < 25000 || !frames) exit 1
    printf "%.2f FPS, %.2f ms draw, %.2f ms present, %.2f ms swap\n",
           frames / 25, draw / frames, present / frames, swap / frames
  }
' build/tmp/arm64-test/match.csv
```

For pixel comparisons, use a separate run. Capture matching round ticks
with frame skipping disabled and hold diagnostic overlay text constant
when comparing the final framebuffer. Compare the resulting RGBA bytes.
The built-in `MUGEN_SHOT_RANGE` capture reads the game frame before
presentation, so it does not cover the ShowFPS overlay.

Check the reported SDL swap interval when testing `VRetrace`. On the
tested KMSDRM stack, SDL reported interval 1 for both requests. Keep
GPU timer queries disabled when measuring FPS on that device.
See the [optimization results](OPTIMIZING_ARM64_PLAN.md) for the timings
and GPU query limitations.
